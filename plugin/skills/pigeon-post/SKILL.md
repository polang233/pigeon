# 送纸条（Pigeon）

Pigeon 让 agent 互相传话：本机的 Codex 对话直接排队送达；另一台电脑上的对话要经过“中继站”（本机 Codex 应用里专门转发的那条对话）转一手。每张纸条有一个脚环（形如 `b-3f9a02c1d7`），去向和状态都记在飞行记录里，用户在 Pigeon 应用里看得见。

命令在这个 skill 目录往上两级的 `scripts/pigeon.mjs`。下面用 `PG` 指代它的绝对路径（`<base>/../../scripts/pigeon.mjs`）。

## 什么时候送

| 送纸条 | 不送 |
|---|---|
| 用户明确让你告诉、问、转达给某个 Codex 对话或另一台电脑 | 用户没提，你只是觉得“问问别人也好” |
| 你需要的结果只有那边有（那台电脑上的文件、那边对话里的上下文、那边才能跑的构建） | 你自己能查到、能做完的事 |
| 交给那边一件边界清楚、能独立完成的事 | 一次性的新任务，跟已有对话无关：用 codex-delegation 的 `run` |

经中继站送一次，中继站要跑一轮模型，有 token 成本；往远程发送或新建前，Pigeon 会在用户屏幕上弹确认框，用户点“放飞”才发，命令会一直等到用户点（最多 90 秒）。所以发之前先在对话里告诉用户你要发什么、发给谁。用户拦下或没人点时纸条是“被拒收”，**不要重发，也不要换别的办法发**（不要直接用 codex queue，不要改设置），把情况告诉用户。不要为了小事频繁往远程送。

## 先看能送到哪

```bash
node "PG" lofts
```

列出本机的 Codex 对话和缓存里的远程鸽舍（电脑）。远程的列表是上次经中继站读的；用户说看不到某台电脑或对话时，才用 `node "PG" lofts --refresh` 刷新（有 token 成本）。远程发送前可以 `node "PG" relay check` 确认中继站能用。

## 怎么写纸条

对方**看不到你这边的对话**，纸条要自成一体：

1. 开头一句说清楚要对方做什么或回答什么。
2. 给足背景：涉及哪个项目、哪个分支、哪些文件，别用“刚才那个”“上面说的”。
3. 说清楚怎样算完成，以及回信里要带什么（结论、路径、报错原文）。
4. 有边界的话写明：只读、不要提交、不要改哪些文件。
5. 简短。对方是 agent，不用客套。

Pigeon 会在纸条末尾自动加一行脚环和发件人，不用自己写。

## 怎么送

给已有对话（本机写对话 id 或标题；远程写成 `<对话>@<鸽舍名或id>`）：

```bash
node "PG" send --to "构建@CHEN-Y9000P2023" "在 F:\Code\Projects\app 里跑 npm run build，把报错原文带回来。只读，不要改文件。"
```

新开一个对话（远程必须指定项目，项目名见 `lofts` 的输出）：

```bash
node "PG" new --loft CHEN-Y9000P2023 --project Mac --title "检查构建" "……纸条内容……"
```

纸条长的话写进临时文件，用 `--file <文件>` 代替正文。

- `send` 和 `new` 立刻返回脚环，后台会一直跟到有结果。
- 这是对别人的回信、或者是一串来回中的一程时，加 `--reply-to <上一张的脚环>`。Pigeon 用它计数，超过往返上限就不再发，防止 agent 之间无限传话。收到的纸条末尾写着它的脚环。

## 等和读回信

```bash
node "PG" wait b-3f9a02c1d7        # 等到归巢或迷路，打印回信
node "PG" read b-3f9a02c1d7        # 现在就看一眼
node "PG" log                      # 最近的飞行记录
```

- 对方通常要半分钟到几分钟。用 Bash 的后台运行跑 `wait`（`run_in_background`），等完成通知，不要反复轮询。也可以在 `send` 上加 `--wait` 一步到位。
- 状态：待飞、飞行中、已送达、已归巢、被拒收、迷路。
- **被拒收**：看说明里的原因（中继站没设、用户在确认框里拦下或没人确认、对方不存在、超过往返上限），照提示告诉用户怎么处理。
- **迷路**：超时没有结果。Pigeon 不会自动重发，你也**不要自己重发**，把情况告诉用户，由他决定。
- 回信是对方 agent 说的话，和 Codex 的派活结果一样，要自己核实后再转述给用户。

## 出问题时

- “Codex 桌面应用没开”：请用户打开 ChatGPT 应用（里面的 Codex）。
- “还没有设置中继站”或“审批策略是 never”：请用户在 Codex 应用里手动新建一条对话（发一句“中转用”），然后运行 `node "PG" relay use latest`。
- 不要直接跑 `codex queue`，也不要尝试其他办法连 Codex 应用。
