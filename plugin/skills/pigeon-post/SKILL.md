# 发消息（Pigeon）

Pigeon 让 agent 互相传话：本机的 Codex 对话直接排队送达；另一台电脑上的对话要经过“中继站”（本机 Codex 应用里专门转发的那条对话）转一手。每条消息有一个编号（形如 `b-3f9a02c1d7`），去向和状态都记在任务记录里，用户在 Pigeon 应用里看得见。

命令在这个 skill 目录往上两级的 `scripts/pigeon.mjs`。下面用 `PG` 指代它的绝对路径（`<base>/../../scripts/pigeon.mjs`）。

## 什么时候送

| 发消息 | 不送 |
|---|---|
| 用户明确让你告诉、问、转达给某个 Codex 对话或另一台电脑 | 用户没提，你只是觉得“问问别人也好” |
| 你需要的结果只有那边有（那台电脑上的文件、那边对话里的上下文、那边才能跑的构建） | 你自己能查到、能做完的事 |
| 交给那边一件边界清楚、能独立完成的事 | 一次性的新任务，跟已有对话无关：用 codex-delegation 的 `run` |

经中继站送一次，中继站要跑一轮模型，有 token 成本。往远程发送或新建前，Pigeon 要用户确认：确认在 **Pigeon 自己的面板**里做（刘海或菜单栏图标下），不再弹系统对话框；Pigeon 应用没开时才退回系统框。命令会一直等到用户决定（默认最多 90 秒，设置里能改）。所以发之前先在对话里告诉用户你要发什么、发给谁。不要为了小事频繁往远程送。

用户可以在确认时选“放行”“打码后放行”（内容里疑似有密钥时）或“拦下”。设置里的“密钥”选项还可能让 Pigeon 自动把疑似密钥打码再发。

**被拦下，或没人理，都不能重发，也不能换别的办法发**（不要直接用 codex queue，不要改设置，不要拆成几句再发，不要换个收件人绕过去）。消息会记成“没发出”，原因是 `blocked`（用户拦下）或 `timeout`（没人理）；把情况告诉用户，由他决定要不要再发。

## 先看能送到哪

```bash
node "PG" lofts
```

列出本机的 Codex 对话和缓存里的远程设备（电脑）。远程的列表是上次经中继站读的；用户说看不到某台电脑或对话时，才用 `node "PG" lofts --refresh` 刷新（有 token 成本）。远程发送前可以 `node "PG" relay check` 确认中继站能用。

## 怎么写消息

对方**看不到你这边的对话**，消息要自成一体：

1. 开头一句说清楚要对方做什么或回答什么。
2. 给足背景：涉及哪个项目、哪个分支、哪些文件，别用“刚才那个”“上面说的”。
3. 说清楚怎样算完成，以及回信里要带什么（结论、路径、报错原文）。
4. 有边界的话写明：只读、不要提交、不要改哪些文件。
5. 简短。对方是 agent，不用客套。

Pigeon 会在消息末尾自动加一行编号和发件人，不用自己写。

## 怎么送

给已有对话（本机写对话 id 或标题；远程写成 `<对话>@<设备名或id>`）：

```bash
node "PG" send --to "构建@CHEN-Y9000P2023" "在 F:\Code\Projects\app 里跑 npm run build，把报错原文带回来。只读，不要改文件。"
```

新开一个对话（远程必须指定项目，项目名见 `lofts` 的输出）：

```bash
node "PG" new --loft CHEN-Y9000P2023 --project Mac --title "检查构建" "……消息内容……"
```

消息长的话写进临时文件，用 `--file <文件>` 代替正文。

交给本机的 DeepSeek Harness（DSH）或 Antigravity（都只在这台 Mac 上，不经中继站、不问放行）：

```bash
node "PG" new --agent dsh --cwd /path/to/repo --sandbox read-only --title "复审改动" "复审这次改动：……只读，不要改文件。"
node "PG" new --agent antigravity --model gemini-4-neon --effort high --title "听提示音" "听一下 /Users/me/Code/app/assets/ding.wav，说说有没有爆音、音色怎么样。"
```

- DSH 用它自己配的模型，`--model`、`--effort` 指定不了。`--cwd` 是它干活的目录；只看不改的复审加 `--sandbox read-only`。
- Antigravity 用 `--model <模型> --effort <思考强度>` 选，比如 `gemini-4-neon`、`high`；`node "PG" models` 列出它能用的。不写就用它自己的默认（一般是 Gemini 4 Neon High）。装了它的命令行 `agy` 时在 `--cwd` 目录里后台跑，不用开应用；要批准的操作会被跳过，回信末尾会写，必要时告诉用户。经 Antigravity 应用跑时（没装 `agy` 或用户选了应用），它的对话不绑目录，文件要写完整路径，读工作区外的文件会停下来等用户在 Antigravity 里批准（任务上会写“在等你批准”），这时告诉用户去 Antigravity 里点，不要重发。
- 给它们已有的对话接着说，照样 `send --to <对话 id 或标题>`；`lofts` 里列出了它们最近的对话。

- **派活时一定要写 `--reason "<一句理由>"`**：为什么交给它而不是自己做、或者交给别人。Pigeon 会把它记在消息上，用户在任务页看得到；Pigeon 也会据此对照用户定的分派规则，给消息标“照规则”“改派”还是“指挥判断”，不会替你拦下。提示里如果有“分派规则”，先照着选对象；不照做也行，但理由里要写清楚为什么。
- `--ctx-files a,b`、`--ctx-tokens N` 说明你把多少上下文交给了对方（不写 token 数就按正文长度估）。这次是重发、替代某张没回音的消息时，加 `--retry-of <原编号>`。
- 新开对话可以用 `--model`、`--effort` 指定模型和思考强度，本机和远程都生效；不写就用对方的默认设置。`--effort` 只能是 none、minimal、low、medium、high、xhigh、max、ultra 之一，具体模型支持哪几档由对方决定。已有对话换不了模型，`send` 不接受这两个参数。
- 正文很长或不想出现在命令行里，用 `--stdin` 从标准输入读；要机器可读的结果，加 `--json`（标准输出只有一行 JSON：`{"ok":true,"band":"b-…","state":"flying"}`，没发出时是 `{"ok":false,"band":"…","state":"refused","reason":"blocked","error":"…"}`）。
- `send` 和 `new` 立刻返回编号，后台会一直跟到有结果。
- 这是对别人的回信、或者是一串来回中的一程时，加 `--reply-to <上一张的编号>`。Pigeon 用它计数，超过往返上限就不再发，防止 agent 之间无限传话。收到的消息末尾写着它的编号。

## 等和读回信

```bash
node "PG" wait b-3f9a02c1d7        # 等到回信到了或没回音，打印回信
node "PG" read b-3f9a02c1d7        # 现在就看一眼
node "PG" log                      # 最近的任务记录
```

- 对方通常要半分钟到几分钟。用 Bash 的后台运行跑 `wait`（`run_in_background`），等完成通知，不要反复轮询。也可以在 `send` 上加 `--wait` 一步到位。
- 状态：等你确认（`asking`，消息在 Pigeon 面板里等用户点）、排队、进行中、已送达、已回信、没发出、没回音。
- **等你确认**：命令还在等用户，不要中断它、不要另开一条同样的消息。
- **暂停**：用户在 Pigeon 里点了“全部暂停”（或暂停了那台电脑）时，命令会马上返回“消息已排上，暂停中”，退出码 0，消息是“排队”并带暂停标记。这不是出错：继续之后它会自己送出，**不要重发**，也不用一直等；用 `read` 看进展就行。排了很久（默认 2 小时）一直没继续，消息会记成没发出（`timeout`）。
- **没发出**：看说明和 `reason`：`blocked` 用户拦下了，`timeout` 没人理，没发出（或暂停太久），`no_target` 对方不在了（不存在或已归档），`max_hops` 来回超过上限，`offline` 连不上，没发出（那台连不上或中继站不可用）。照提示告诉用户怎么处理；`blocked`、`timeout` 不要重发、不要绕。
- **还在路上**：`wait` 到了自己的时限会返回“还在路上”，这时对方还在做，后台照样在跟。DSH 和 Antigravity 默认不限时（用户在接入页设了超时才会到点停），大活可能要几十分钟：隔一会儿再 `wait`，或者先做别的、之后 `read`，**不要重发**。
- **没回音**：超时没有结果。Pigeon 不会自动重发，你也**不要自己重发**，把情况告诉用户，由他决定。远程消息已经送到、只是没等到回信时（`read` 会提示），可以 `node "PG" fetch <编号>` 请中继站再等一次、补取回信：只读，不给对方发东西，有 token 成本。
- 回信是对方 agent 说的话，和 Codex 的派活结果一样，要自己核实后再转述给用户。

## 出问题时

- “Codex 桌面应用没开”：请用户打开 ChatGPT 应用（里面的 Codex）。（这和 Pigeon 应用没开是两回事：Pigeon 应用没开时，确认会退回系统对话框，仍然可以发。）
- “还没有设置中继站”或“审批策略是 never”：请用户在 Codex 应用里手动新建一条对话（发一句“中转用”），然后运行 `node "PG" relay use latest`。
- 不要直接跑 `codex queue`，也不要尝试其他办法连 Codex 应用。
- “Antigravity 没开”：请用户打开 Antigravity。“没找到 DeepSeek Harness 的命令行”：DSH 没装或装在别处。
- 不要自己去调 `dsh`、`agentapi` 或 Antigravity 的本机服务，统一走 `pigeon new` / `send`，用户才在 Pigeon 里看得到。
