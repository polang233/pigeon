# Pigeon 需求文档

> 界面方向在 2026-11-12 改了：不再以像素鸽舍为主，改成普通的应用界面，鸽舍和办公室降为可选样式。新方向的需求和进度见 [REDESIGN.md](REDESIGN.md)，这套界面已经在 `web/` 里做成正式界面（原来的 `prototype/` 已删除）。本文描述的是上一版，功能部分仍然有效，但用词和界面已经变了：现在叫设备、消息、任务、对话，不再用鸽舍、纸条、脚环、栖木这套词；界面也换成了新的应用界面（2026-11-14）。现行的说法见 [REDESIGN.md](REDESIGN.md)，接口见 [CONTRACT.md](CONTRACT.md)。

## 一句话

Pigeon 让你的 agent 互相传话：跨工具，也跨电脑，每张纸条的去向你都看得见。

名字来自信鸽：它们带着纸条在不同的住处之间往返，正好是这个应用做的事。原名 Meerkat（狐獴），改名的原因见 `IMPLEMENTATION.md` 末尾。

## 要解决的问题

现在同时用好几个 AI 编程工具（Claude Code、Codex 等）很常见，它们之间却没有一条能看得见的传话通道：

- Claude Code 想让 Codex 帮忙做件事，只能一次性开个新任务，没法给 Codex 里已经有的对话发一条消息，也读不到回复。
- Codex 已经可以连接别的电脑，但从 Claude Code 这边够不到那些电脑上的对话。
- 传话的过程散落在终端输出里：发出去没有、对方接了没有、做完没有、回信是什么，都要自己去翻。
- 人不盯着屏幕时，没有办法知道哪件事做完了，或者卡在等你批准上。

## 使用场景

1. Claude Code 在写代码时，给本机一个正在跑构建的 Codex 对话送纸条："构建 main 分支，把报错带回来"，等它归巢后读回信。
2. 在另一台电脑（比如一台 Windows 机器）上有一个 Codex 对话，Claude Code 经过本机 Codex 的中继站给它送纸条，或在那台电脑的某个项目里新开一个对话。
3. 派出任务以后去做别的事，只靠屏幕上沿的栖木看一眼："两张在飞，一件在等你"。
4. 事后想知道一张纸条发给了谁、花了多久、有没有迷路：看飞行记录。
5. 开着 Claude Code 干活时，把 Pigeon 放在屏幕一角，看子代理和交给 Codex 的活怎么分头进行（这是沿用旧版的功能）。

## 名词

| 英文 | 中文 | 指的是 |
|---|---|---|
| Loft | 鸽舍 | 一台电脑。本机的 id 固定是 `local`，远程的 id 是 Codex 给的主机 id（形如 `remote-control:env_…`） |
| Flock | 鸽群 | 一台电脑上的各个 agent |
| Note | 纸条 | 一条消息 |
| Band | 脚环 | 纸条的编号，形如 `b-` 加 10 位十六进制，比如 `b-3f9a02c1d7` |
| Perch | 栖木 | 贴着刘海或屏幕上沿的小提醒条 |
| Waystation | 中继站 | 本机 Codex 桌面应用里，专门用来转发纸条的那条对话 |

## 角色和画面

画面是黄昏的屋顶。本机是近处的大鸽舍，每个 agent 是一只有辨识度的鸽子，各有一根栖木；别的电脑是远处屋顶上的小鸽舍，按实际能连到的设备出现。

| 角色 | 形象 | 位置 |
|---|---|---|
| 本机的鸽舍 | 近处屋顶上的大鸽舍 | 画面近处 |
| Claude Code | 带锈橙色的铜翅鸽 | 本机鸽舍，各占一根栖木 |
| Codex | 颈羽是薄荷绿的白鸽 | 同上 |
| Cursor | 带银色翅斑的炭灰鸽 | 同上 |
| DeepSeek | 头顶有冠羽的蓝鸽 | 同上 |
| 信鸽（纸条） | 蓝灰色的岩鸽，从发件人飞向收件人 | 两者之间 |
| 子代理 | 雏鸽，派活时在本机鸽舍内短途飞行 | 主人旁边 |
| 远程鸽舍 | 远处屋顶上的小鸽舍，上面是那台电脑的对话，最多画 4 个 | 画面远处 |

跨鸽舍的纸条要飞过中间的天空。画面全是代码一格一格画的像素图，放大也不糊。旧版的"像素工作室"保留为"旧版"主题。

**屏幕上的栖木**是另一个独立的小面板，不在画面里：它贴在刘海下沿（没有刘海的屏幕贴在上沿正中）。收起时是一条很小的胶囊，显示一只鸽子和"N 在飞 · N 等你"，全部空闲时几乎透明；全屏应用下不会自动隐藏；鼠标移上去或点击会展开，列出飞行中的纸条和等你处理的事。它不抢键盘焦点；开关在设置页、菜单栏菜单和"显示"菜单里。超过 2 小时没有任何消息的纸条，应用会当作过期，不再计数。

## 纸条的六种状态和画面

| 状态 | 中文 | 含义 | 画面 |
|---|---|---|---|
| `queued` | 待飞 | 已经排进队列，对方还没接 | 鸽子在发件人的栖木上等着 |
| `flying` | 飞行中 | 正在送：对方已接手，或中继站正在转发 | 沿弧线飞向收件人；跨鸽舍时飞过天空 |
| `delivered` | 已送达 | 对方开始处理 | 鸽子落在收件人的栖木上 |
| `home` | 已归巢 | 对方这一轮结束，回信已取回 | 带着回信飞回发件人 |
| `refused` | 被拒收 | 发送被拒：你在确认框里拦下、对方不存在、超过往返上限 | 被弹回，有明显的拒收表现 |
| `lost` | 迷路 | 超时没有结果。不自动重发 | 鸽子在空中打转后消失，和被拒收的表现明显不同 |

画面只在关键时刻用力：一次放飞、一次归巢。上面各状态具体怎么演，以当时的 `web/js/theme-loft.js` 为准（已删除，新界面不再有这套动画）。系统开了"减少动态效果"时画面会收敛动效。同时恢复显示的纸条最多 10 张。

旁边的列表叫"飞行记录"，分"纸条"和"派活"两页；纸条页里每条有脚环、从谁到谁、状态、用时和预览。点一条能看到回信预览，以及打开 Codex 对话的链接。

## 数据从哪来

1. **插件的 `pigeon` 命令**：送纸条、新开对话、等待、读回信都由它完成。它把飞行记录写在 `~/.pigeon/journal.json`，把鸽舍和对话的缓存写在 `~/.pigeon/lofts.json`，并把每次状态变化作为 `PigeonNote` 事件发给应用。日志里不存纸条正文，事件里只带最多 80 字的预览。
2. **本机 Codex**：用 `codex queue` 往已有对话排消息；对话的进展和最终回复从 `~/.codex/sessions` 下的记录文件里读；本机对话列表从 `~/.codex/state_5.sqlite` 只读查询。
3. **远程 Codex**：只能通过 Codex 桌面应用里的工具操作，所以经过中继站转发。
4. **Claude Code hook**：由插件的 `forward.sh` 转发给应用，用来展示子代理和派活（沿用旧版）。`Agent` / `Task` 工具是子代理任务；`mcp__codex*` 工具或 Bash 里执行 `codex` 是 Codex 任务；开始和结束按 `tool_use_id` 配对。
5. **`pigeon run`**：把 Codex 的执行过程作为 `PigeonRun` 事件报给应用。
6. **本机检测和用量**：应用自己看 Codex、Cursor、Claude 有没有安装和在运行；token 用量来自 Claude Code 和 Codex 自己的对话记录，只在本机统计。
7. 应用内置只监听本机的小服务（`127.0.0.1:47321`），随应用启动、随应用退出。接口见 `CONTRACT.md`。

## 限制

- **Claude Code 只能当发件方。** 往 Claude Code 的会话里投递消息没有验证过，这一版不做。
- **不能在栖木上直接审批。** Codex 里需要审批的事，仍然要回到 Codex 里点。
- **跨电脑必须经过中继站**：要在本机 Codex 桌面应用里手动建一条对话（命令行建的对话审批策略是 `never`，会拒绝发送和新建）；每次转发要跑一轮模型，有 token 成本；发送和新建前 Pigeon 会弹框让你确认（Codex 自己不为这类发送弹审批，默认开，可在设置里关）；Codex 桌面应用必须开着。本机对话之间的纸条不经过模型，没有这个成本。
- 在远程电脑上新开对话，要求那台电脑上已经在 Codex 里保存了对应的项目。
- 本机对话收到纸条后，要等 Codex 桌面应用开着，大约 10～15 秒后才会接手。应用没开时纸条会一直排着队，超时后标"迷路"。
- 本机新开对话用 `codex exec`，建出来的对话审批策略是 `never`，所以不能当中继站，在它里面也调不了跨设备的工具。
- 远程新开对话必须指定项目（那台电脑只保存了一个项目时可省略）。
- 超时的纸条只标"迷路"，不会自动重发。
- 为了防止互相无限回信，每条纸条链有往返上限，默认 10 次，超过就拒发。
- Codex 内部做了什么看不到，只能从它的对话记录里读到每一轮的最终回复。
- 子代理内部的工具调用，只有 hook 里带 `agent_type` 时才能归到子代理头上，否则算在 Claude 身上。
- Cursor 和 DeepSeek 目前只检测在不在线，不能收发纸条。

## 范围

**这一版**
- 命令入口 `pigeon`：`lofts`、`send`、`new`、`wait`、`read`、`log`、`relay`，以及原有的 `run`、`settings`、`doctor`、`open`。
- 本机 Codex 对话的送信，和经中继站的远程送信。
- 防循环、超时标"迷路"、日志不存正文。
- Claude Code 插件：hook 转发，`pigeon-post` 和 `codex-delegation` 两个 skill。
- Mac 应用：改名为 Pigeon、栖木、菜单栏鸽子图标、系统通知、`/api/notes` 和 `/api/lofts`、设置自动迁移。
- 画面：鸽舍主题、飞行记录、设置页的"送信"和"栖木"、模拟演示里的送信剧本。
- 沿用旧版的子代理和 Codex 派活展示、用量统计、`pigeon run`。

**这一版不做**
- 往 Claude Code 的会话里投递消息。
- 在栖木上直接审批。
- 自动重发迷路的纸条。
- 官网（`site/`）的更新，等功能做完再重做。
- 直接连 Codex 桌面应用的工具 socket（实测会被立刻断开，不要尝试绕过）。

**之后可以考虑**
- 解析 Codex 对话记录，看到它内部的真实动作。
- 历史回放，更长时间的飞行记录。
- 让 Cursor 等更多 agent 参与送信。
