# Pigeon 新界面方案

2026-11-12 定的方向。上一版界面（`web/`，像素鸽舍）看着不像能日常用的工具，这一版改成普通的应用界面，先保证好用。本文记录新方向的需求、原型做到了哪一步、哪些已经验证、哪些还只是设想。

可点的原型在 `prototype/`，全部是示例数据，不连任何服务。正式界面 `web/` 和 Mac 应用 `mac/` 还没有按这一版改。

## 要做成什么

Pigeon 让一个 agent 指挥别的 agent 干活，包括别的电脑上的 agent，并且让你随时看得到、拦得住。

- **指挥和接活。** 一个对话当指挥（现在是 Claude Code），把活分给 Codex、Cursor、DeepSeek Harness。接活的 agent 也能回信，或者继续往下派。
- **跨设备。** 活可以派到另一台电脑上。那台电脑如果只连了 Codex，别的 agent 就经 Codex 带起来。
- **少让用户操作。** 接入一个 agent 只改它自己配置里的几行，改之前列出来给用户看，能单独撤回。
- **不开窗口也能处理。** 等你确认的事、到了的回信，在刘海或屏幕侧边就能处理。

## 界面用词

界面里不再用鸽舍、纸条、脚环、栖木这套比喻词，直接叫设备、任务、消息、对话。产品名仍然是 Pigeon。办公室和鸽舍两套像素画面保留，降级成指挥台的可选样式。

命令行和现有文档（`README.md`、`PRD.md`、`CONTRACT.md`）还在用旧词，正式改界面时再一起换。

## 页面

| 页面 | 内容 |
|---|---|
| 指挥台 | 一台设备一页，底部像角色页那样翻页（左右方向键也能翻）。指挥在左边，接活的 agent 往右排开，有任务在跑的连线会动；别的电脑在指挥那一页上收成一张卡片，点卡片右上角的按钮展开。右侧是选中对象的详情 |
| 任务 | agent 之间发出的每一件事：谁给谁、什么状态、走到哪一步、回信、为什么交给它、交出去多少上下文。跨设备的任务在这里放飞或拦下 |
| 分派规则 | 哪类活交给谁。上面是流向图，下面是能直接改的规则表，再下面是额度阈值和写进指挥提示里的样子；输入一句任务能看到它逐条怎么判、最后交给谁 |
| 接入 | 一张卡片一台设备，可以添加和移除设备。卡片里一行一个 agent：怎么接的、能不能发能不能收、订阅剩多少、开关。一键接入前先列出会改哪几个文件。下面是协作的规矩 |
| 刘海 | 不再是单独一页。五种状态（收起、悬停总览、等你处理、回信到了、快速派活）在设置的刘海一节用"演示"按钮看。设置里能关掉刘海，关掉后同样的面板从菜单栏的鸽子图标展开。没有刘海的外接显示器上，在屏幕顶部正中画一个同样的黑色胶囊。侧边条去掉了，不如刘海好用 |

### 指挥台怎么显示

参考 magpie 的画法：画面上只放身份和状态，在做什么不写在画面上，说明都放进悬停提示。

- **节点。** 每个节点只有会动的形象、名字和一排小圆点，一个圆点是一个对话，小一号的圆点是它拆出的子对话。
- **形象会动。** 简洁样式里头像按此刻在做什么换动作：
  - Claude Code 用 [clawd-tank](https://github.com/marciogranzotto/clawd-tank) 的像素 SVG 动画（MIT，`prototype/art/clawd-tank/`，原样未改）：往外派活时指挥，有子代理在跑时杂耍，在想时头顶冒气泡，跑构建时戴安全帽挥锤子，其余在干活时对着笔记本打字；等你时提醒，完成时开心，空闲时发呆，还没对话时睡觉，出错时挠头。所有动作用同一个取景框对到头像上。
  - Codex 用它应用里自带的宠物 `codex`：深蓝色的小云团，脸上一块屏幕显示 `>_`。从本机 Codex 应用（`ChatGPT.app` 的 `app.asar`）里原样取出，放在 `prototype/art/local/`，这个目录不提交。
  - DeepSeek 是照 Clawd 的十个动作换了身子的像素鲸鱼（`prototype/art/crew/`，由 `prototype/tools/crew_svg.py` 生成）：动作和道具和 Clawd 一样，躯干换成翘尾巴的蓝鲸鱼，没有腿，身子一直到地面，底下一块浅蓝的肚皮。
  - Codex 的宠物是 Codex 宠物的格式（每帧 192×208，8 列 × 11 行，一行一个动作），按状态播对应那一行：干活播"跑"，往外派活播"挥手"，在想播"审查"，等你播"等待"，完成播"跳"，出错播"失败"，空闲播"待机"，还没对话时停住、压暗。加载不到时退回各家的像素标志。
  - **Codex 的宠物没有授权，版权归 OpenAI，只能在原型里先用，正式版不能内置。** 正式版可以做成读取用户本机 Codex 里的宠物（自带的和 `~/.codex/pets/` 里装的），或者让用户自己从 petdex 导入。
  - Cursor 在 petdex 上找不到宠物，先放它的像素标志，按状态动一动：干活时上下晃，等你时一跳一跳，在想时左右歪，出错时抖。
  - 中间试过 Google 的 Noto 动画表情、自己照 clawd-tank 画另外三家、vibe-svgs 的光泽矢量形象、petdex 上的金色 `>_` 圆环和像素鲸鱼 Whaley，都不合适，撤掉了。
- **状态框。** 在干活的头像外还有一道转圈的光，等你的是闪烁的红框加"!"，刚完成的挂一个绿勾。
- **信鸽。** 任务是沿着连线飞的信鸽，颜色跟着发信的 agent：Claude Code 发出去的是橙色鸽子，Codex 回信是绿色鸽子。跨设备等你确认的，鸽子停在那一段的半路扑腾得更快，外面一圈红色波纹。
  - 画成会自己动的 SVG（`prototype/art/brand.js` 的 `pigeon`），画法和 clawd-tank 一样：一格一个方块拼出身子，翅膀整块绕着肩膀上下扇，身子跟着一起一伏。朝右飞，脖子一圈绿紫的光泽，嘴上一点白，翅膀上两道深色的斑，脚下挂一封封了红蜡的白信封，信封跟着轻轻晃。
  - 同一只鸽子还有三种样子：停在指挥头上的那只收着翅膀，偶尔低头啄一下；刘海下面飞的那只小一号；白天天上飞过的鸽群不挂信。
- **模型和思考。** 名字下面一行写正在用的模型（等宽小字），后面四格小竖条是思考强度（低、中、高、极高）。正在干活时竖条一起起伏，表示正在思考。悬停看全称；右侧详情里也写着。
- **连线。** 默认是像素折线：从头像右边出发，拐一个圆角的弯进到下一个头像左边，一格一格的小方块，颜色从发的一方渐变到收的一方。有任务在送时方块一格一格往前走，回信往回走，等你确认的那段变红、一闪一闪。跨设备的一段方块两两成对；靠收信那头有一个小圆标，标出是怎么连的（Codex 应用内、SSH），悬停看说明。设置里可以换回上一版的弧线。
- **订阅剩余。** 默认不在指挥台上画，鼠标移到 agent 上时，提示里写着模型、这个时间窗剩多少（一根小条）、套餐、多久后重置、本周剩多少、今天接了几件；低于分派规则里的阈值时标红，写明会先改派给别人。设置里可以改成一直显示：头像右下角一个小圆盘，绿、黄、红表示剩得多、一半、快没了。按量付费的写"按量付费，没有订阅额度"。
- **全部暂停。** 指挥台右上角"全部暂停"：Pigeon 不再送出任何消息，在路上的停在原地，正在干活的 agent 做完这一轮就停。暂停时舞台顶上一条横幅，连线上的鸽子停住，底部轮播写"已暂停"，刘海左侧写"已暂停"。接入页每台设备也能单独暂停，指挥台底下那台的标签上挂一个暂停的小标。
- **场景。** 指挥头上停着一只鸽子，偶尔低头啄一下；指挥身后一圈很淡的光。浅色时是白天：右上角一个像素太阳，几朵云慢慢飘过，偶尔有一小群鸽子排成人字飞过去。深色时是夜晚：一片会闪的星星、一弯月亮，偶尔划过一颗流星。设置里可以关掉。
- **底部轮播。** 一次一行，轮流显示这一页正在发生的事，对应的连线和节点同时亮起来。右边是在干活、等你、回信的数量。
- **细节在哪看。** 悬停节点出一个小提示，列出它的对话；点一下在右侧详情里看全部和操作。窗口窄于 1080 时详情收起，点节点才从右边滑出来。
- **布局。** 一张看不见的网格。默认指挥在最左边，往右一列一层，像往右边发任务；一层里从上往下排，父节点放在它的孩子中间。舞台够宽时隔一列放，铺得开一点；不够宽时挤一挤，放不下的上下排，连线改成从下边出、进上边。舞台大时节点跟着放大。
- **排布。** 按网格自动排：指挥在左，往右一列一层，父节点在它的孩子中间。第一版不能拖（原来的拖动、吸附、位置记忆都去掉了）。

### 指挥台的层级

- **经 Codex 中转。** 远程设备是经 Codex 应用内连的，线就从指挥所在那台电脑的 Codex 连过去，而不是从指挥直接连。经 SSH 连的设备，线从指挥直接出去。
- **别的设备那一页。** 指挥所在的那台收成一张卡片放在最左边，和指挥那页上收起的远程设备一样：顶上是设备名，下面是它接的几个 agent 的 logo，指挥挂一个指挥台的小标。线从这张卡片连到这台的入口。悬停写明"指挥在这台 · 经它的 Codex 连到这台"，点一下翻回指挥那页。这张卡片不能展开；这一页的"等你"数字和底部轮播只算这台自己的。
- **远程设备收起和展开。** 在指挥那一页上，每台远程设备默认收成一张横跨两格的卡片：顶上是设备名和连接方式，下面是它接的几个 agent，只有 logo 和框（框的颜色表示状态，入口挂一个门的小标）。
  - 展开：点卡片右上角的按钮。展开后它的几个 agent 像本机的一样排在网格上，身后铺一块淡色的底，标着设备名。
  - 收起：点那块底右上角的按钮。
  - 点卡片其他地方，或者键盘聚焦后按回车、空格，翻到这台设备自己那一页。
  - 舞台太窄、放不下两格时，卡片缩成一格，里面的 logo 变小。
- **入口。** 远程设备只连了 Codex 时，Codex 头像上挂一个门的小标，悬停写明"入口"。
- **子连接。** 那台设备上的其他 agent 挂在入口外面，用点线连到入口。
- **子对话。** 一个对话自己往下拆出来的对话，显示成它后面小一号的圆点；在悬停提示和详情里缩进列出。

### 形象

各家 agent 用它们真实标志的像素版，在 `prototype/art/brand.js` 里画成 16×16 的网格，界面各处的小图标和办公室里的角色用同一张图：

- Claude Code：橙色的小螃蟹 Clawd。
- Codex：蓝紫色圆团，中间一个终端提示符。
- Cursor：实心的六边形立方体，中间挖空一块向下的三角。单色，浅色模式是黑的，深色模式是白的。
- DeepSeek Harness：往上翘尾巴的蓝鲸鱼。

身份色（鸽子、刘海光带用）：Claude Code 橙，Codex 绿，Cursor 跟着文字颜色，DeepSeek 蓝。Codex 的标志本身是蓝紫色，身份色用绿色是为了和 DeepSeek 的蓝分开。

### 配色和设置

侧栏底部的“设置”里可以改这几样，记在浏览器里：

- **外观。** 跟随系统、浅色、深色。
- **配色。** 两套：
  - 经典（默认）：中性的深浅灰，就是最初那一版。
  - 信鸽：深色是夜航（深蓝黑底、纸白字），浅色是信纸（暖白底、墨色字），按钮和选中用鸽子脖颈的青绿。
- **场景。** 白天黑夜（跟着明暗走）或关。
- **连线。** 像素折线（默认）或弧线。
- **刘海。** 开（默认）或关。关掉后屏幕顶上不画刘海面板，菜单栏右边多一个鸽子图标，有事等你时挂一个红色数字，点一下从它下面展开同一个面板。
- **订阅额度。** 悬停时看（默认）或一直显示。
- **跨设备发送前查密钥。** 提醒（默认）、自动打码或关。提醒：消息里像 npm token、GitHub token、API key、AWS 密钥、Slack token 的字符串标红，放飞时可以选"原样放飞"或"打码后放飞"；自动打码：对方收到的是"‹npm token 已打码›"这样的占位符。
- **演示。** 刘海五种状态的演示按钮；"来一件转派""来一件拆活"往等你处理的一队里加一件；"CHEN 断开"开关，演示设备连不上。
- **场景样式（实验）。** 简洁（默认）、洋馆、办公室、鸽舍。第一版只做简洁。

### 样式

指挥台右上角可以切四种样式：简洁（默认）、洋馆、办公室、鸽舍。选过的样式记在浏览器里。办公室和鸽舍还是早先的样子，没有跟着加订阅圆盘和场景。

- **洋馆。** Claude 大小姐指挥大家干活的一座洋馆大厅，人物和背景都是 Codex 用内置生图画的动漫插画（2026-11-12）。
  - 画风：当下中文互联网主流的 AI 娘 Q 版表情包风格（二头身、大眼、干净描线、赛璐璐上色）。
  - 人物按我们写的设定原创，只借大家认得的特征，提示词里写明不模仿任何画师和已有角色：
    - Claude 大小姐：暖橙色长直发、花形发饰、黑色胸衣配橙色泡泡袖和长裙，拿着书。
    - DeepSeek 鲸鱼娘女仆：圆滚滚，蓝发、背鳍呆毛、小鲸鳍、女仆装、V 字大尾巴，爱吃白米饭。社区流行的女仆鲸鱼娘是在原创角色"溟月"上二次设计的，原作者禁止商用，我们没有参照它的图。
    - Codex 龙娘：白色长卷发、龙角龙翼龙尾、白裙外套深灰连帽衫、`>_` 发卡，会画画也会写代码。
    - Cursor 娘（社区里没有，我们设计的）：黑色波波头带银灰挑染、六边形立方体发饰、黑白极简套装、杖头是鼠标箭头的长杖。
  - 每个角色一张 3×3 九宫格动作表（同一张图里画九个状态，脸和衣服才一致），用 `prototype/tools/slice_sheet.py` 切成九张、统一按脚底对齐，放在 `prototype/art/manor/<agent>/`。九个状态：立绘、指挥或收到吩咐、干活、在想、等你、完成、空闲、睡着、出错。
  - 指挥台按 agent 此刻在做什么换图，再加一点 CSS 小动作让静态图活起来：空闲时呼吸，干活时上下轻晃，指挥时左右摆，在想时歪头，等你时一跳一跳，完成时小跳，出错时抖两下，睡着时慢慢呼吸。
  - 大厅：白天版和夜晚版同一个构图，浅色用白天、深色用夜晚。窗外屋顶上有个小鸽舍和几只信鸽，夜里鸽舍亮着灯。原图在 `assets/generated/`，原型里用压缩过的 JPEG。
  - 收起的远程设备是一块挂着的木牌，金边；展开时身后铺一块金边的底。
  - `prototype/art/manor.js` 里还留着一版自己画的像素人物和像素大厅，图片缺失时用它顶上。
- **办公室。** 每个 agent 一个工位：显示器、桌子、坐在桌后的角色，头顶气泡表示状态。
- **鸽舍。** 沿用 `web/js/loft-art.js` 里原来的屋顶和鸽子（原型里是软链接，没有复制），每只鸽子右下角挂它家的小标志。

### 接入：设备和 agent

- **设备卡片。** 一张卡片一台设备，标题旁写着它是怎么连的（本机、Codex 应用内、SSH）。
- **设备改名。** 点卡片上的设备名就地改，回车或点别处保存，Esc 取消，清空就恢复原来的名字；指挥台底下的设备标签双击也能改。改过名的，悬停名字能看到电脑本来的名字。改名只改显示，不影响连接。没改过名时本机显示"本机"，别的电脑取电脑名"-"前那段；改过就到处都用新名字。
- **默认模型。** agent 一行里的模型是个按钮，点开在下面展开：这家能用的模型、思考强度。本机装了 magpie 时多一行它的路由组（比如 `group/smart` 先用最快重置的订阅），选了路由组，思考强度就由 magpie 决定。这里只管 Pigeon 派活、新开对话时默认用什么，不改它自己的配置；刘海上派活时还能临时换。页头写着"magpie 已连上"。
- **agent 一行。** 依次是 logo 和名字；接法标签（插件、Hook、MCP、应用操作；远程的是应用内、经 Codex、SSH）；能发、能收两个小箭头，绿色是已实测，黄色是有做法但没验证，灰色是做不到；订阅圆盘；开关。经入口带起的 agent 缩进，用一根线挂在入口下面。所有说明都在悬停提示里。
- **添加设备。** 两步：先选怎么连（Codex 应用内、SSH、经 magpie；本机 magpie 没开时"经 magpie"点不了），再选哪台电脑、起个名字（不填就用电脑名）、接哪些应用。经 Codex 连时默认"只连 Codex"：那台电脑不用装 Pigeon，Codex 是入口，勾上的其他应用由它带起；关掉这个开关就是在那台电脑上也装 Pigeon，直接接这些应用。SSH 填地址，选的应用都经 SSH 启动。加完后指挥台多一页，本机那页多一条从 Codex（或指挥）出去的线。
- **经 magpie 添加。** 第二步列出本机 magpie 里加过的远程 magpie（名字和电脑名），选中后逐条检查：已加成远程 magpie（地址）、它的 MCP 服务已加进本机 Library、那台装了 Pigeon 小助手（找到哪些应用）。没过的一条标红并写怎么补，"添加"点不了。下面一句说明：没看到那台要先在那台 magpie 打开局域网共享、在这台加成 Remote magpie，钥匙要不限额。接哪些应用只能选小助手在那台找到的。加完后那台的 agent 接法都是"经 magpie"，线从指挥直接出去；那台自己那页上，指挥这台的卡片悬停写"经 magpie 连到这台"。原型里远程 magpie 是三台示例。
- **移除设备。** 远程设备卡片右上角的按钮，原型里直接移除，没有二次确认。
- **暂停一台。** 设备卡片右上角的暂停按钮，暂停后卡片上挂"已暂停"。
- **协作的规矩。** 多了两条，默认都开："接活的 agent 往下转派前问我"、"指挥一次拆给 3 件以上时问我"。问的事都排进刘海里那一队。

### 刘海上派活

点指挥台的"派活"或刘海页的"快速派活"，刘海往下展开：

- **对象。** 按设备分行，每行是那台设备上接着的 agent（logo 加短名）。
- **模型。** 选中对象后列出它能用的模型，默认是它在接入里配的那个；装了 magpie 的，后面跟着它的路由组（虚线框）。
- **思考强度。** 和节点上一样的竖条，点第几格就是哪一档，后面写着低、中、高、极高。每个模型分的档不一样，不分的写"不分思考强度"；换模型时如果原来那档没有，就落到中间那档。
- 每个对象各记一份选过的模型和思考强度，写了一半的话换对象也还在。发到本机是新开一个对话，跨设备的还要你确认一次。
- 能不能真的指定：Codex 新开对话时可以指定模型和思考强度，Claude Code 和 Cursor 的命令行能指定模型，DeepSeek Harness 还没查。

### 刘海上等你的事

等你处理的事排成一队，点刘海右边的"N 件等你"或悬停总览顶上那一条展开：

- **三类。** 跨设备发送（红标）、接活的 agent 往下转派、指挥要拆活。每条一行：类别、谁发给谁的 logo、一句话、时间。
- **展开选中的那条。** 跨设备的写明发到哪台、要发的原文、带了几个文件、多少上下文、90 秒不点就当拦下；转派的写明谁想转给谁、命中哪条规则；拆活的列出拆成哪几件、各给谁。
- **操作。** 拦下、放行（拆活是"全部放行"），每条都能"跳回对话"，回到发起的那个对话所在的应用（本机的在它自己的应用里打开，别的电脑上的经本机 Codex 打开）。转派的还有"以后直接转"，等于关掉协作规矩里那一条。
- **键盘。** 上下选，回车放行，⌫ 拦下。
- **全部暂停。** 队列底下一个按钮，和指挥台上的是同一个。暂停时放行的先排着，继续后再送出。
- 刘海上派到别的电脑的活，也排进这一队等你放行。

### 刘海上的信鸽

把刘海当成一颗星球。刘海下沿的光带每个 agent 一段，用身份色；有信要送时，鸽子从发信那一段起飞，往下扎出去，被"引力"拉回来，落到收信那一段，身后留一串渐隐的小点。横向匀速、竖向受朝上的恒定引力，所以是一条挂在刘海下面的抛物线，越靠近底部飞得越慢，往下时低头、往回时抬头。起飞那段会闪一下，落地那段会亮一下。原型里每 4 秒轮流飞一条正在送或刚回来的信，点"放飞"也会飞一只。

## 分派规则怎么生效

规则是给指挥看的建议，写进给它的提示里，最后由它自己判断，Pigeon 不替它决定。跨设备的任务不管规则怎么写，默认都要用户点一次确认。

- **匹配。** 从上到下，第一条命中的算数。一条规则是"当任务是"一句话加一组关键词；交给的那家不在了（设备移除或关了）就跳过这条往下看。
- **额度参与派活。** 每条规则可以写"额度不够时"改派给谁。交给的那家订阅额度低于阈值（默认 20%，可选 10、20、30、50）时，按改派那一栏派；没写改派的照常派，提示里会告诉指挥它快用完了。按量付费的不受影响。
- **写进提示里的样子。** 页面底下直接显示：每条规则一行，额度不够的写明"它的额度现在只剩 16%，先交给某某"，要确认的写明"发之前要用户确认"，最后要求指挥派活时附一句理由，没照建议做也说明为什么。指挥每开新一轮时更新一次。
- **为什么给它。** 任务页每一行带一个小标签：规则几、额度改派、指挥改判（规则建议了，指挥没照做）、指挥判断（没有规则命中）。点开写明完整的理由；指挥自己判断的那件可以"照这件加一条规则"，命中规则的可以"在分派规则里看"，会把这件的标题填进试算框。
- **规则表。** 每条有开关；"当任务是"和关键词直接改；交给谁、额度不够时、发之前都是下拉；本周命中几次，指挥没照做几次；拖左边的把手调先后；悬停出删除。
- **流向图。** 左边指挥，中间每条规则，右边交给的各家，每家旁边一根额度小条。实线是交给，虚线是额度不够时的改派；正在改派的那条虚线变黄。悬停规则或者试一句，走到的那条线会动起来，其他的变淡。
- **试一句。** 逐条列出每条规则怎么判（没命中、关着、命中、命中但额度不够改派），最后一句写交给谁、要不要问你。

## 接 magpie 能拿到什么

2026-11-13 查了 magpie 的文档（usemagpie.ai/docs/integrate、仓库里的 `docs/reference.md`）和源码，又在本机装着的 magpie 0.1.3929 上读了几个接口，没改它任何设置。

它在本机 `127.0.0.1:3425` 开着一个网关，端口以 `~/.config/magpie/settings.json` 里的 `port` 为准（只读，不写）。`GET /api/hello` 回 `{"name":"magpie"}` 就是它。本机读不用钥匙。别的电脑来读，要那台开"局域网共享"并带一把网关钥匙；给 Pigeon 的用只读钥匙（`magpie gateway-key add Pigeon --read-only`），花不了钱。Pigeon 自己调网关时用 `magpie-pigeon` 当钥匙，magpie 的用量页里就记在 Pigeon 名下。

| Pigeon 要的 | magpie 的接口 | 实测 |
|---|---|---|
| 订阅额度、多久后重置 | `GET /v1/magpie/quotas`；常读加 `?kept=1`，只给上次读到的，不去问厂商。每张卡写着哪家、订阅/套餐/余额、每个时间窗用了百分之几、什么时候重置，`last` 标出最近答话的那个账号 | 读到 6 张：Cursor、两个 ChatGPT（Codex 用的）、Kimi、两个 DeepSeek 余额。没有 Claude 的，magpie 里没有 Claude 这一家 |
| 别的电脑上的额度 | 那台的 magpie 共享出来、这台把它加成"远程 magpie"后，它的卡也在上面那个接口里，`from` 写着那台的名字 | 没试 |
| 默认模型的选项 | `GET /v1/models`：模型 id（含 `group/<名字>` 路由组、`auto/<模型>`）、思考强度有哪几档、上下文多长 | 9 个模型，没建路由组 |
| 为什么给它，说到模型这一层 | `GET /v1/magpie/route?session=<会话 ID>`：这一轮命中哪个路由组、哪条规则，试了哪些模型、哪个失败了换下一个，最后谁答的。第一个字出来前就有，能长轮询跟着。Claude Code 自己的会话 ID 就能用 | 没试，要一个正在跑的会话 |
| 每件任务花了多少 | `GET /v1/magpie/usage`、`/v1/magpie/usage/requests`：按会话、按 agent 的调用次数、token、按官价折算的钱 | 今天经它走的只有 Codex，469 次调用 |
| 指挥台上谁在干活 | `GET /v1/magpie/concurrency`：正在进行的每个请求，哪个 agent、哪个模型，在排队（等额度或速率限制）还是在等厂商回。可以每秒读；`/v1/magpie/route-events` 是实时推送 | 读到了，当时没有进行中的 |
| 交出去的上下文占多少 | 分母用 `/v1/models` 里的上下文长度；要交出去的原文用 `/v1/messages/count_tokens` 数 | 上下文长度读到了 |
| 统一的 MCP 一次装到各家 | 打开 magpie 的 MCP 路由后，Pigeon 的 MCP 在它的 Library 里加一次，每个连着 magpie 的 agent 只多一个 `magpie` 条目，经它转给 Pigeon。agent 要重启一次 | 没试；默认关着，Claude 桌面版用不了 |

### 两台都装 magpie：经它跨电脑派活

查的是 magpie 的 MCP 路由和远程 magpie（仓库 `docs/subsystems/mcp-router.md`），没实测。链路是这样的：

1. 那台电脑（比如 CHEN）装 magpie 和 Pigeon 的一个小助手。小助手是一个 MCP 服务，提供"发消息、新开对话、看回信"几个工具，收到调用就在那台本地把消息交给 Codex、Claude Code 这些应用。它加进那台 magpie 的 Library，打开 MCP 路由和局域网共享。
2. 这台把那台加成远程 magpie，打开"把它的 MCP 服务加进 Library"。这台的 magpie 就多了一个指向那台路由的服务。
3. Pigeon 调这台 magpie 的 `/mcp/magpie/hub`（本机不用钥匙），工具名像 `chen__pigeon__send`。这台 magpie 转给那台，那台 magpie 起小助手，小助手在那台本地发起。

和现在经 Codex 中转比：

| | 经 Codex 中转（现在） | 经 magpie |
|---|---|---|
| 那台要装 | 只要 Codex 应用 | magpie 和 Pigeon 的小助手 |
| 网络 | Codex 自己的远程连接 | 同一个局域网；不在一个网里要用 Tailscale 这类组网，或者给那台的 magpie 一个公网地址 |
| 那台能接的应用 | 由 Codex 带起 | 小助手能起的都行，不经 Codex |
| 顺带得到 | 无 | 那台的额度、用量、路由都能在这台读到 |

要注意的：

- **钥匙权限偏大。** 能起那台程序的钥匙不能限额、限模型（限了的钥匙只能用别处的 HTTP 服务，跑不了那台的程序），所以它同时也能不限量地用那台的订阅。退一步可以让小助手在那台本机开一个 HTTP 端口，加进 Library 的是这个地址，限过的钥匙也能用。
- **一次调用 50 秒内要回。** 工具只负责把消息交出去就回"已排队"，回信靠这台定时调"看回信"去取。
- **只转一层。** 经路由转来的请求不会再转给第三台，A 经 B 到 C 不行。
- **路由默认关着。** 打开后各家 agent 的 MCP 配置会被 magpie 换成一个 `magpie` 条目，要重启一次。
- 也可以把小助手做成 magpie 的工具插件（npm 包，在 magpie 的插件里跑），装起来更省事；插件里能不能起别的程序没查。

### magpie 还能做的、和 Pigeon 有关的

- **Library 的说明文件。** 写一份说明，magpie 写进每个勾上的 agent 每次对话前都读的说明里。分派规则写给各家 agent 看，可以走这条，不用一家一家改。
- **共享记忆。** 一个 agent 学到的偏好，别的 agent 第二天也知道。经一个 MCP 服务和说明里的一段摘要。
- **会话列表和继续。** 它读各家 agent 的会话文件，能列出来，"继续"按钮给出在终端里接着这个对话的命令。"跳回对话"可以借它。
- **短期钥匙。** 按次发一把几分钟到几天就失效的钥匙，可以限模型、限 token。给远程那台、给沙盒里跑的 agent 用。
- **网关中间件插件。** 请求经过时改写请求和回复，可以在网关这一层做查密钥、加提示。
- **OTLP 导出。** 把每次调用发到可观测平台。

做不到或要注意的：

- **只看得到经 magpie 走的请求。** 没连 magpie 的 agent，用量、路由、谁在干活都没有。额度不受影响，它是按账号读的。
- **额度按账号，不按 agent。** 要按 agent 用的模型前缀（`codex/…`、`cursor/…`）对上账号；同一家有两个账号时，看 `last` 或这个会话的路由。
- **没有接口改某个 agent 的默认模型。** 命令行能改（`magpie claude group/xxx`），但会写 agent 自己的配置。Pigeon 打算新开对话时带上模型参数（比如 `claude --model group/xxx`），只在那个 agent 连着 magpie 时管用。
- **路由组看不到规则。** 管理接口还不包括路由组（magpie 的 #6307 在做），现在只能从 `/v1/models` 列出名字。
- **意图分类没有单独的接口。** 它只在 magpie 路由组的规则里用。Pigeon 想按意思匹配分派规则，可以经网关调一个便宜的小模型自己判。
- **同步只管 magpie 自己的设置**（包括各 agent 选的模型），放不进 Pigeon 的规则和设备名。
- **打码只在它发给厂商时做**，没看到能单独调用的接口。
- **没有手机端。**

## 参考了什么

- **magpie**（usemagpie.ai）：一行一个 agent 的配置面板、流向图式的路由画面、改配置只动自己那几行。
- **clawd-on-desk**（github.com/rullerzhou-afk/clawd-on-desk）：盯着 Claude Code、Codex 等 20 多个 agent 的像素桌宠，12 种状态由 agent 的回调驱动，能导入 Codex 宠物。它的状态划分值得照着做；它的美术保留所有权利，不能拿。它只看状态，不在 agent 之间派活、传消息，这是和 Pigeon 的主要区别。README 里有一张对比表。
- **clawd-tank**（github.com/marciogranzotto/clawd-tank）：Clawd 的像素 SVG 动画，MIT 许可，Claude Code 直接用它。
- **petdex**（petdex.dev）：5000 多只 Codex 宠物，统一的精灵图格式。试过给 Codex 和 DeepSeek 用其中两只，后来都换掉了；宠物的版权归投稿人，大多没写许可证。
- **vibe-svgs**（github.com/imMamdouhaboammar/vibe-svgs）：AI 编程工具的社区形象 SVG，MIT 许可。试过，画风不合适，没用。

## 重构前定下的事

2026-11-13 定的。第 2、3、5 件是按建议先定的默认，想改随时改。

### 谁是指挥

- 同一时间只有一个指挥。能往外发的 agent 都能当：Claude Code、Codex、Cursor、DeepSeek Harness。接入页标着"不能发出"的 agent 不给"设为指挥"。
- 也可以是**你**：在 Pigeon 里自己派活（刘海上的快速派活、指挥台的"派活"）。这时指挥台中心是"你"，回信回到任务页和刘海的"回信到了"，没有 agent 帮你接着处理，要你自己看。接口里发件人 `from.agent` 本来就有 `you` 这个值。
- 换指挥不影响在路上的任务，回信按发件人回去。

### 等你处理的那一队

有几种事 Pigeon 不替你做主，要停下来问你：发到别的电脑、接活的 agent 要往下转派、指挥一次拆成 3 件以上。这些事排成一队，就是刘海上的"N 件等你"。定下来的是：

- **在哪问。** 在 Pigeon 自己的刘海面板里问（刘海关了，就是菜单栏鸽子图标下的同一个面板），不再弹系统对话框。现在插件的 `confirm.mjs` 弹系统框，重构时改成问应用；应用没开时才退回系统框。
- **多久不理算什么。** 跨设备发送 90 秒没人点就不发，写"没人理，没发出"，和你点"拦下"分开显示。转派和拆活不限时，一直排着。时间在设置里能改。
- **键盘什么时候算数。** 只在面板展开、并且鼠标或焦点在面板里时生效。回车放行选中的那条；焦点停在某个按钮上时，回车就是按那个按钮（停在"拦下"上就是拦下）。Esc 收起，面板右上角也有关闭按钮。
- **暂停时。** 全部暂停时点"放行"，那条先排着，继续后再送出。
- **规矩要生效。** 接入页"协作的规矩"里关掉哪一条，那类事就不再排进这一队，直接做。

### 分派规则谁来判

- Pigeon 先按规则算出建议：交给谁、额度不够时改派谁、发之前要不要问你。建议写进指挥的提示里。
- 指挥自己决定，派活时必须附一句理由（派活工具的 `reason` 参数）。
- Pigeon 不判第二次，也不拦，只对照着打标签：和建议一致标"规则 N"或"额度改派"，不一致标"指挥改判"，没有规则命中标"指挥判断"。
- 指挥是你的时候没有提示可写：派活面板里先把建议的对象选好，你可以改。
- 第一版按关键词匹配。以后可以经 magpie 调一个便宜的小模型按意思判。

### 刘海用原生窗口

刘海和菜单栏面板用 AppKit 的原生浮动窗口（`NSPanel`，Mac 端 `Perch.swift` 已经有一个不抢焦点的），不用网页。原型里用网页画只是为了定交互，重构时照着它的五种状态和上面的键盘规则做原生版。

### 网页不再支持双击打开

现在正式版的 `web/index.html` 不开应用、在 Finder 里双击用浏览器打开，也能看模拟演示。为了这个，代码只能写成一串按顺序加载的普通脚本，不能拆成模块。定下来不再支持：应用本来就经自己的本机服务（`127.0.0.1:47321`）加载网页；想单独看演示，用 `python3 prototype/tools/serve.py`。这样新界面能拆成模块、写单元测试。

### 第一版的范围

- 场景样式只做简洁；洋馆、办公室、鸽舍收进设置，标"实验"。
- 去掉"刘海"那一页，演示按钮挪进设置的刘海一节。能做到什么程度只留在本文档里。
- 指挥台自动排布，不能拖；远程设备用按钮展开、收起。
- 接入页不写"已实测""没验证"，只写能不能。
- `prototype/` 就是新界面前端的骨架：示例数据只在一个文件里，正式重构时换成读应用接口的那一层，再搬进应用。接口要补的字段见 `CONTRACT.md` 的"新界面要的数据"。
