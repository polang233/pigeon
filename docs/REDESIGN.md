# Pigeon 新界面方案

2026-11-12 定的方向。上一版界面（`web/`，像素鸽舍）看着不像能日常用的工具，这一版改成普通的应用界面，先保证好用。本文记录新方向的需求、原型做到了哪一步、哪些已经验证、哪些还只是设想。

可点的原型在 `prototype/`，全部是示例数据，不连任何服务。正式界面 `web/` 和 Mac 应用 `mac/` 还没有按这一版改。

## 要做成什么

Pigeon 让一个 agent 指挥别的 agent 干活，包括别的电脑上的 agent，并且让你随时看得到、拦得住。

- **指挥和接活。** 一个对话当指挥（现在是 Claude Code），把活分给 Codex、Cursor、DeepSeek Harness。接活的 agent 也能回信，或者继续往下派。
- **跨设备。** 活可以派到另一台电脑上。那台电脑如果只连了 Codex，别的 agent 就经 Codex 带起来。
- **少让用户操作。** 接入一个 agent 只改它自己配置里的几行，改之前列出来给用户看，能单独撤回。
- **不开窗口也能处理。** 等你确认的事、到了的回信，在刘海或屏幕侧边就能处理。

## 界面用词

界面里不再用鸽舍、纸条、脚环、栖木这套比喻词，直接叫设备、任务、消息、对话。产品名仍然是 Pigeon。办公室和鸽舍两套像素画面保留，降级成指挥台的可选样式。

命令行和现有文档（`README.md`、`PRD.md`、`CONTRACT.md`）还在用旧词，正式改界面时再一起换。

## 页面

| 页面 | 内容 |
|---|---|
| 指挥台 | 指挥在正中，接活的 agent 围着它，有任务在跑的连线会动。可以按设备分页，也可以按 agent 分页，底部像角色页那样翻页（左右方向键也能翻）。右侧是选中对象的详情 |
| 任务 | agent 之间发出的每一件事：谁给谁、什么状态、走到哪一步、回信。跨设备的任务在这里放飞或拦下 |
| 分派规则 | 哪类活交给谁。上面是流向图，下面是规则表；输入一句任务能看到它会被建议交给谁 |
| 接入 | 一行一个 agent：能发出什么、能接收什么、怎么接的、开关。一键接入前先列出会改哪几个文件。下面是协作的规矩（是否允许互相派活、跨设备前先问我、连续来回上限） |
| 刘海与侧边条 | 演示屏幕顶上的五种状态：收起、悬停总览、等你确认、回信到了、快速派活。没有刘海的屏幕用侧边条 |

### 指挥台的层级

- **入口。** 远程设备只连了一个 agent 时，这个 agent 标"入口"，指挥的线只连到它。
- **子连接。** 那台设备上的其他 agent 挂在入口下面，用点线连到入口，写明"经 Codex 带起"。
- **子对话。** 一个对话自己往下拆出来的对话，缩进排在它下面。
- **布局。** 卡片按实际大小自动避让，指挥留在正中。窗口窄或一页超过四个节点时换紧凑卡片，并把舞台加高。

### 样式

指挥台右上角可以切三种样式：简洁（默认）、办公室、鸽舍。只换指挥台这一块，卡片位置和连线不变，其他页面不变。办公室和鸽舍直接用 `web/js/sprites.js` 和 `web/js/loft-art.js` 里原来的像素画（原型里是软链接，没有复制）。

## 分派规则怎么生效

规则是给指挥看的建议，写进给它的提示里，最后由它自己判断，Pigeon 不替它决定。跨设备的任务不管规则怎么写，默认都要用户点一次确认。

## 刘海上能做到什么程度

| 事情 | 程度 |
|---|---|
| 两侧显示谁在干活、几件事等你 | 能做 |
| 悬停展开总览，不抢焦点 | 能做，现在的栖木已经有 |
| 就地确认跨设备发送，代替系统对话框 | 能做 |
| 回信到了看摘要，一键转给指挥 | 能做 |
| 快速派活（点一下才拿键盘焦点，或全局快捷键呼出） | 能做 |
| 批准 Claude Code 的工具权限 | agent-hud-open 已经这样做，我们没验证 |
| 把文件或文字拖到刘海上派活 | 系统支持，交互要新做 |
| 批准 Codex 自己的审批 | 只有明确交给用户审阅的那一轮才行，其余只能提醒并带过去 |
| 全屏时常驻 | 默认隐藏，可设成有事等你时才出现 |
| 批准 Cursor 中途的操作 | 做不到，它的回调只在一轮结束时触发 |
| 画进物理刘海里面 | 做不到，只能画在两侧和下方 |

## 接入各个 agent 的打算

| agent | 它发出 | 它接收 | 怎么接 | 现状 |
|---|---|---|---|---|
| Claude Code（本机） | 插件里的命令 | 等它空闲时送进去 | Claude Code 插件 | 发出已实测；接收没验证 |
| Codex（本机） | 一个 MCP | 排进它的队列，不打断当前一轮 | 加一个 MCP 和两条回调 | 接收已实测（`codex queue` 加唤醒）；MCP 还没做 |
| Cursor（本机） | 一个 MCP | 只在它一轮结束时收 | 加一个 MCP 和一条回调 | 没做，没验证 |
| DeepSeek Harness（本机） | 一个 MCP | 排进它自己的队列 | Harness 插件 | 没做，没验证 |
| Codex（远程） | 暂时只能回信 | 发消息、新开对话 | 经本机 Codex 中转，那台电脑不用装东西 | 已实测，见 `IMPLEMENTATION.md` |
| 其他 agent（远程） | 暂时只能回信 | 由远程的 Codex 启动并转交 | 走 Codex 这条连接 | 只是设想，没验证 |

## 参考了什么

- **magpie**（usemagpie.ai）：一行一个 agent 的配置面板、流向图式的路由画面、改配置只动自己那几行。
- **agent-hud-open**（agenthud.app）：刘海悬停展开、就地批准、回到会话、侧边条上图标之间传信。它的 agent 互发消息是免费功能，只在同一台电脑上传；收费的是手机和手表远程。跨设备是我们和它的区别。

## 现在做到哪了

**已经能用的（上一版就有，已实测）**

- 给本机 Codex 对话发消息、新开对话，并取回回信。
- 经本机 Codex 给远程电脑上的 Codex 发消息、新开对话，并取回回信。
- 跨设备发送前弹框确认，放飞、拦下、超时三条路都在真对话框上试过。
- 任务记录不存正文，防止 agent 之间无限来回。

**原型里做好的（只是界面，示例数据）**

- 五个页面和页面之间的跳转。
- 指挥台：按设备和按 agent 两种分页、翻页、入口和子连接、子对话、自动避让、紧凑卡片。
- 三种样式切换。
- 刘海的五种状态和侧边条。
- 明暗两套配色。

**原型检查过的**

- 820、1094、1320 三种宽度下，按设备和按 agent 的每一页，简洁和鸽舍样式都没有卡片重叠或出界。办公室样式用同一套排布，没有单独跑这项检查。
- 控制台没有报错。

**还没做的**

- 把新界面搬进正式的 `web/`，接上真实数据。
- Mac 应用里的刘海面板按新交互重做（现在的栖木只有提醒和悬停展开）。
- 统一的 MCP、Cursor 和 DeepSeek Harness 的接入。
- 分派规则的保存和注入。
- 经远程 Codex 带起别的 agent。
- 办公室样式里 DeepSeek Harness 没有专属角色，暂用通用小角色。
- 开启"减少动态效果"时的画面没有看过。
