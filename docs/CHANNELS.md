# 项目频道（设计稿）

2026-11-22 起草，2026-11-23 最后一节"要定的事"按建议的默认定下。打算放进 0.3，先用演示数据做 0.3a 的可点原型；接真数据时再改 `CONTRACT.md` 和 `DESIGN.md`。

## 要解决什么

现在 agent 之间的往来只在任务页里一行一行列着：谁给谁、什么状态、一小段预览。几件事连起来是在做同一个项目，这在界面上看不出来；你想插一句话、把一件事交给另一个 agent，得回到 Claude Code 里让指挥去发。

最近不少多 agent 工具的做法是：一个对话就是一个 agent，几个 agent 拉进一个群，在群里 @ 谁谁就干活。这个交互很直观，Pigeon 也做，但做法不一样：

- **Pigeon 不托管对话。** agent 照样在 Claude Code、Codex 自己的应用里干活，工具调用、代码改动、权限审批都留在原处。Pigeon 做的是它们之间的群：群里一条消息就是一次派活，回信回到群里。
- **群按项目分。** 一个项目（一个代码目录）一个频道，成员是在这个项目里干活的那几个对话，可以跨工具、跨电脑。

## 不做什么

- 不在 Pigeon 里显示工具调用、改动和审批，不替代各家自己的应用。要看细节就"跳回对话"。
- 不把每条消息发给群里所有 agent。只有被 @ 的才收到，见"谁收到消息"。
- 不让 agent 在群里自由闲聊。agent 之间的来回有上限，到了就停下来等你。

## 概念

- **频道**：一个项目一个。有名字、对应的项目目录（可以有几个，比如本机和 CHEN 上同一个仓库的两个路径）、成员、一个指挥。可以归档。
- **成员**：一个已有的对话（哪家 agent、在哪台设备、哪个对话），或者"你"。还可以 @ 一个 agent 但不指定对话，表示给它新开一个对话，开好后那个对话自动加进频道。
- **指挥**：每个频道一个，默认就是全局的指挥（现在是 Claude Code 或你）。不 @ 谁时消息交给它。
- **消息**：频道里的一条。有四种：
  - **派活**：@ 了谁。对应现在的一条任务记录（一个 `band`），多了频道和正文。
  - **回信**：对方这一轮结束时取回的结果，挂在它回的那条派活下面。
  - **留言**：只写给频道看，不送给任何 agent，比如"这个先别动，等我周一看"。
  - **系统**：谁加入了、谁被拦下了、频道暂停了这类，一行灰字。
- **一串**：一条派活加上它的回信、接着问的，按现在的 `chain` 折成一串，默认只显示最后一条，点开看全部。

## 谁收到消息

这是频道最要紧的规矩，定错了要么 token 烧得快，要么 agent 之间停不下来。

1. **@ 了谁，谁收到。** @ 几个就是同时派给几个，每个各开一串，各自回信。
2. **没 @ 谁，交给指挥。** 指挥按分派规则自己判断交给谁，和现在一样。只想记一笔、不想让任何 agent 收到，就切成"留言"。
3. **收到的人拿到什么。** 消息正文，加一段频道背景：
   - 频道名、项目目录、成员名单（谁在哪台设备上）；
   - 最近几条的摘要（默认 8 条，每条最多 160 字），让它知道前面在说什么；
   - 怎么回：落款里的编号，和现在一样。
   
   背景整段最多 1500 字，设置里能调。这一段比把整个群的记录塞给它省得多。
4. **回信自动回到频道。** 挂在它回的那条下面，同时照旧送回发信的人。
5. **agent 自己 @ 别人。** 要接活的 agent 也能主动发，得先有统一的 Pigeon MCP（见 `TODO.md` 的"统一的 MCP"）。在那之前，回信里写到"@Codex""交给 Codex"时，频道把它显示成一个"转给 Codex"按钮，由你点。
6. **停得下来。**
   - 一串最多传几次，沿用现在的 `post.maxHops`（默认 10）；
   - 新加一条频道级的：没有你插话时，agent 之间最多连续来回几次（默认 6），到了这个频道自动暂停，刘海上排一件"等你"；
   - 发到别的电脑照旧先问你，不变；
   - 全部暂停、单台设备暂停也对频道生效。

## 消息存多少

现在任务记录里不存正文，只有 80 字的预览，应用一重启标题就变成"（内容没保存）"。群聊要留得住历史，所以频道要存正文：

- **只存在本机。** 每个频道一个文件 `~/.pigeon/channels/<频道 id>.jsonl`，一行一条，只往后追加。频道列表另存 `~/.pigeon/channels.json`。
- **存多久。** 默认 30 天，设置里可以改，也能一键清空某个频道或全部。
- **单条上限。** 正文超过 2 万字的截断，写明截掉了多少。
- **像密钥的字符串。** 按发出去时的样子存：你选了"打码后放行"就存打码后的。
- **不想存。** 设置里能关，关了就和现在一样只留预览。
- `journal.json` 不变，照旧记每条消息的状态；频道文件里的消息用 `band` 对上它。

## 界面

侧栏改成：指挥台、频道、分派规则、接入。任务页并进频道：原来的表格变成频道页里的"全部"视图。

```
┌─────────────┬──────────────────────────────────────┬──────────────┐
│ 频道         │ pigeon  ~/Code/Projects/pigeon       │ 成员          │
│             │──────────────────────────────────────│              │
│ ● pigeon  2 │  你                                    │ Claude Code  │
│   magpie    │  @Codex 把刘海光带加粗一点             │   指挥 · 在干活│
│   site      │                                       │ Codex        │
│             │  Codex · 本机          已回信 3 分钟   │   本机 · 空闲 │
│ ─────────── │  光带改成 3pt，空闲亮度 0.55……         │ Codex @CHEN  │
│ 全部         │  [接着问] [转给…] [跳回对话]            │   等你确认    │
│             │                                       │              │
│             │  Claude Code → Codex @CHEN   等你确认  │ + 拉进来      │
│             │  在 Windows 上跑测试集……  [放行][拦下]  │              │
│             │──────────────────────────────────────│              │
│ + 新频道     │ [@ 交给谁 ▾] 写点什么……       [发出] │              │
└─────────────┴──────────────────────────────────────┴──────────────┘
```

- **左栏：频道列表。** 项目名，未读几条，有等你的事标红；下面是"全部"，就是现在的任务表格，筛选照旧。
- **中间：消息流。**
  - **派活**：发件人 → 收件人，状态（排队、进行中、已回信……），点开看"为什么给它""交出去多少上下文"，和现在任务页的展开一样。
  - **回信**：显示全文，下面是"接着问""转给…""跳回对话"三个按钮。
  - **等你确认的**：放行、拦下的按钮直接在这条消息里。
- **右栏：成员。** 每个成员的状态、模型、额度；点一下跳回对话；"拉进来"从已有的对话里挑。
- **输入框。** 打 @ 弹出成员，后面跟着"Codex（新开对话）"这类还不在群里的 agent；选了别的电脑上的，发之前照旧问你。模型和思考强度的选法和刘海上的快速派活一样。
- **刘海。** "回信到了"写明是哪个频道；快速派活多一个频道选择，默认最近用过的那个。
- **指挥台。** 不变。点一条在跑的连线，打开对应频道里的那一串。

## 频道怎么来

- **自动建。** 一条消息的发件或收件对话的目录，落在某个频道的项目目录里，就归进那个频道；没有就按目录新建一个，名字取目录名。远程电脑上的路径（比如 `F:\Code\Projects\pigeon`）第一次出现时问你一次"这是不是 pigeon 这个项目"，记下来以后自动归。
- **手动拉群。** 新建一个频道，挑几个对话拉进来，不管它们在哪个目录。
- **合并、拆开、改名、归档。** 自动建错了能合并到别的频道。归档的频道不再接收新消息，历史还能看。

## 指挥怎么用频道

- 插件发消息时自动带上频道：按当前对话的目录找频道，找不到就新建。`pigeon send`、`pigeon new` 多一个 `--channel <id>`，不写就按目录找。
- 新增 `pigeon channel read [--since <编号>]`：指挥用它读频道里你写的话和别人的回信，接上前面的进度。
- **你在频道里写的话，怎么送到 Claude Code。** Claude Code 现在不能接收（`TODO.md` 的"Claude Code 能接收"）。第一版先走现成的路：插件每一轮已经在指挥的提示里追加分派规则，顺便追加一句"频道里有 2 条新消息：……"。缺点是要等你在 Claude Code 里说下一句话才送得到。能实时送进去以后再换。

## 接口草案

定下来以后搬进 `CONTRACT.md`。

`~/.pigeon/channels.json`：

```json
{
  "version": 1,
  "channels": [
    {
      "id": "ch-7c1e9a",
      "name": "pigeon",
      "paths": [ { "loft": "local", "path": "/Users/me/Code/Projects/pigeon" } ],
      "members": [
        { "agent": "claude", "loft": "local", "session": "…", "role": "lead" },
        { "agent": "codex", "loft": "local", "session": "…" },
        { "agent": "you" }
      ],
      "maxAgentTurns": 6,
      "paused": false,
      "archived": false,
      "created": 1794370024000
    }
  ]
}
```

`~/.pigeon/channels/<id>.jsonl`，一行一条：

```json
{ "id": "m-3f9a02", "ts": 1794370024000, "kind": "task", "band": "b-3f9a02c1d7", "chain": "b-3f9a02c1d7",
  "from": { "agent": "you" }, "to": [ { "agent": "codex", "loft": "local", "session": "…" } ],
  "body": "把刘海光带加粗一点", "truncated": 0 }
```

`kind` 取 `task`（派活）、`reply`（回信）、`note`（留言）、`system`。

本机服务新增：

| 请求 | 说明 |
|---|---|
| `GET /api/channels` | 频道列表，带每个的未读数和等你的件数 |
| `POST /api/channels` | 新建（手动拉群） |
| `PATCH /api/channels/<id>` | 改名、改成员、合并、归档、暂停 |
| `GET /api/channels/<id>/messages?before=<id>&limit=50` | 往前翻历史 |
| `POST /api/channels/<id>/messages` | 你在频道里发一条（留言，或 @ 谁派活） |

推送新增 `PigeonChannel` 事件：频道里多了一条、某条状态变了、频道改了。
