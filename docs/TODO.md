# 待办

0.2.0 之后要做的事，2026-11-16 整理。分两类：

- **大方向**：要新做一块功能、换平台或者改架构，通常要先定方案。
- **小改进**：bug、体验细节、配置和代码结构的调整，在现有架构里就能改。

每条尽量写清现在是什么样、要改成什么样。做完的从这里删掉，写进 `CHANGELOG.md`。哪些已经验证、哪些没有，见 `DESIGN.md` 的"现在做到哪了"。

## 大方向

### 平台和刘海

- **Windows 版。** 现在只有 Mac 版。命令行和插件是 Node 写的，大部分能跑，但有三处只有 Mac 才有：跨设备确认退回的系统对话框（`osascript`）、Codex 应用的路径和检测、`codex://` 跳回对话。应用本身（本机服务、窗口、刘海）要重写一份，或者换成能跨平台的壳。要先定的几件事：
  - 用什么做：Tauri、WinUI，或者 Electron。网页界面 `web/` 可以直接复用，本机服务的接口照 `CONTRACT.md` 实现一遍。
  - Windows 上没有刘海，"等你处理"放在哪：托盘图标弹出的面板，还是屏幕顶部正中的胶囊。
  - 开机自启和托盘常驻。
- **刘海的灵动岛样式。** 现在的刘海面板展开、收起都是直接跳到新尺寸。要做成像 iPhone 灵动岛那样：从刘海里长出来、有弹性地伸缩，内容跟着状态变宽变高，收起时缩回刘海。
- **分清几种屏幕。** 要分别做、分别试：
  - MacBook Pro 和 Air 的刘海宽度、高度不同；
  - 外接显示器没有刘海，现在画一个 120pt 的胶囊；
  - 全屏应用里怎么显示；
  - 多块屏幕时放在哪一块。
  - 这些都还没有在真机上看过。
- **刘海的交互没有人手试过。** 自动测试覆盖了按键规则，但真的悬停、点击、Tab 聚焦、在派活框里打字、从菜单栏展开，都还没人手操作过。这一项和上面的灵动岛样式一起做，你提到的那些小问题也一起记到这里。

### 更多 agent 能发、能收

- **统一的 MCP。** 给 Codex、Cursor、DeepSeek Harness 装同一个 Pigeon MCP，它们才能当指挥、往下转派、给别人回信。有了它才能做这几件：
  - 等你处理的一队里的"转派前问我"（relay）和"拆活前问我"（split），现在接口留着，没有来源；
  - 派活工具的 `reason` 参数，让 Codex 等当指挥时也能写理由；
  - 别的指挥也能收到分派规则。现在规则只写进 Claude Code 的提示（`prompt-hint.mjs`）。
- **Claude Code 能接收。** 现在 Claude Code 只能发出。要在它空闲时把消息送进去：可以经插件的 hook，或者开新对话。
- **接入 Cursor 和 DeepSeek Harness。** 现在检测到了只显示"还没接上"。Cursor 只能在一轮结束时收；DeepSeek Harness 还没查清它能怎么接。
- **一键接入本机。** 接入页上的"一键接入"在第一版里藏起来了。要做成：列出会改哪几个文件、改哪几行，改完能单独撤回。
- **经远程 Codex 带起别的 agent。** 远程电脑只连了 Codex 时，经它启动那台的 Claude Code、Cursor。现在只是设想。

### magpie 联动

- **经 magpie 跨电脑。** 两台都装 magpie 时，经 magpie 的 MCP 路由把活交给那台的 Pigeon 小助手。小助手要新做，是一个 MCP 服务，提供"发消息、新开对话、看回信"。添加设备里"经 magpie"现在是置灰的。方案和要注意的地方（钥匙权限偏大、50 秒内要回、只转一层）见 `DESIGN.md`。
- **别的电脑上的额度。** 现在只读本机 magpie 的额度，远程的写"读不到"。那台的 magpie 共享出来、这台加成远程 magpie 后就能读到。
- **路由组和模型说到 magpie 这一层。**
  - 路由组读 `/v1/models` 里的真名字；
  - "为什么给它"接上 `/v1/magpie/route`，说到这一轮最后是哪个模型答的；

- **规则发给所有 agent。** 用 magpie 的 Library 说明文件，把分派规则一次写给所有连着 magpie 的 agent，不用一家一家改。
- **跳回对话借 magpie 的会话列表。** 现在 Claude Code 只能切到它的应用，打不开具体对话。

## 小改进

### 刘海

- 展开、收起没有动画，是直接跳过去的。这条和上面的灵动岛样式一起做。
- Tab 能不能聚焦到按钮，要看系统设置里有没有打开"键盘导航"。没打开时，"焦点在拦下上按回车就是拦下"这条规矩用不上。
- 远程设备派活时不列模型。早先以为远程新开对话指定不了模型，现在命令行已经能经 `create_thread` 指定了，`NotchBridge` 和网页上的默认模型要跟着接上。远程能用哪些模型，现在拿的是本机 Codex 的列表，不一定准。
- 刘海设成隐藏时，设置里的"演示"按钮按了没反应。
- 信鸽沿光带飞的动画写了，但没有人看过。
- 没有全局快捷键呼出快速派活（原型里是 ⌥ 空格）。
- "转给指挥"按钮没有后端，现在藏起来了。
- Claude Code 等你批准权限时，只能"跳回对话"，不能在刘海上直接批准。

### 本机服务和命令行

- **刘海和本机服务之间还在传 JSON。** `NotchBridge` 把本机服务的数据先编成 JSON 再解出来喂给刘海，刘海和应用在同一个进程里，可以直接用 Swift 类型；`CONTRACT.md` 里的接口也可以改写成 JSON Schema，几处实现（Swift、网页、插件）照它校验。两件都要动不少代码，先记着。
- **发给 Codex 的落款和中继指令还是旧词。** 落款是"（Pigeon 纸条 b-…，来自…）"，中继指令里也有。要先在真的 Codex 上试过，再改成新词。
- **应用晚开就看不到已经在跑的任务。** `pigeon run` 只在开始时报一次"开始"，应用那时没开就收不到，之后的进度和结束也对不上任务。应用启动时可以读 `~/.pigeon/running/` 和 `runs/`，把正在跑的任务补回来。
- **拦直接调 Codex 的 hook 会误判。** `route-codex.mjs` 在整条 Bash 命令里找 `codex exec`，heredoc 或注释里写到这几个字也会被拦下。要只看真正执行的命令。
- **Codex 应用的列表不列 Pigeon 派的活。** `codex exec` 开的对话在 Codex 里只能靠 `codex://` 链接打开，跑着的时候只能看、不能接着说。要真的出现在列表里，得改成经 Codex 应用新开对话（像 `pigeon new` 那样）。
- **命令行写设置还是整份写。** `plugin/scripts/lib/common.mjs` 的 `patchSettings` 先读完整设置，改完整份 `PUT` 回去，和网页之前的问题一样：读和写之间别处改的会被盖掉。要改成 `PATCH`。
- **应用重启后，任务标题变成"（内容没保存）"。** 任务记录里不存正文，预览只在事件里有。要定的是：把 80 字的预览存进任务记录，还是保持现在这样。
- **应用自己派的活，重启后不能重发。** 原文只在内存里。
- **队列编号每次启动从 q1 开始。** 只在内存里用，现在没问题；以后要是持久化，得换成不会重复的编号。
- **子代理对上是猜的。** Claude Code 子代理的工具事件只带 `agent_id`，现在按"最早一个还没认领的子代理"来对。同时跑几个子代理时可能对错。
- **出错状态可能永远出不来。** 现在按 `StopFailure` 这个 hook 名来认出错，这个名字是猜的。Claude Code 不发这个事件的话，对话就永远不会显示"出错"。
- **任务页里不认识的对话显示"没列出的对话"。** Claude Code 的主对话不在最近列表里时会这样，应该显示目录名或者最近一句话。
- **两个只给自动测试用的开关也在正式包里。** `PIGEON_HEADLESS` 和 `PIGEON_SNAPSHOT_DIR` 打进了正式包。要决定只在调试版里留，还是保留但写清楚。
- **端口固定是 47321。** 被占用时应用直接退出。可以改成自动换一个，再告诉插件。

### 配置文件结构

- **`settings.json` 里还有旧版留下的字段。** 有这几个：
  - `scene.seats`、`scene.layout`、`scene.showSubLabels`：旧的像素工作室用的；
  - `perch.enabled`：现在用 `perch.notch`；
  - `codex.showInCodex`：现在用 `codex.sessionMode`。
  - 要做的：加 `version: 2`，启动时迁移一次，删掉旧字段。
- **状态分散在四个地方。** 要梳理哪些该放哪：
  - `~/Library/Application Support/Pigeon/settings.json`：设置；
  - 浏览器的 localStorage：外观；
  - `~/.pigeon/`：任务记录 `journal.json`、设备和对话缓存 `lofts.json`、分派规则写进提示的原文 `dispatch.json`、`runs/`；
  - 应用的内存：等你处理的一队、发出的原文。
- **分派规则存在设置里，派生的提示原文另存一份。** 规则在 `settings.dispatch.rules`，写进提示的原文在 `~/.pigeon/dispatch.json`，后者由网页算好再交给应用。网页没打开时，额度变了也不会更新提示原文；现在主窗口关掉或最小化半分钟后网页会被释放，这种时候更多了。应该改成应用自己算，网页只负责编辑规则。
- **跨设备确认的等待时间上限。** 界面上最多 100 秒，可设置文件里能写更大。插件那边要跟着限制，或者在应用侧统一检查。
- **何时停掉 Meerkat 时期的兼容。** 旧设置路径、`MEERKAT_*` 环境变量、`meerkat-codex.mjs` 入口、`mk-` 前缀都还兼容着，要定一个版本停掉。
